# DSH 桌面接续

命令行模型调用报 `DSH_DESKTOP_REQUIRED` 时使用。默认等待 240 秒，可用 `--timeout` 调整。超时时脚本会先检查命令行输出和已保存的会话，能核实的完整回复直接取回。已有交接文件时，可先用原参数运行一次检查原会话是否已完成，这一步不会重新调用模型。只有仍需接续时才使用 Computer Use。验收命令超时按本机验证失败处理。

等待时可查看本轮 `*.status.md`。超时会尝试结束本轮脚本启动的进程及子进程，再检查结果。若 DSH 桌面未响应，先保留交接记录和其他验证证据，待桌面可用后再决定是否接续。

从会话取回回复时，脚本读取 DSH 的本地压缩会话记录。本流程已验证 DSH Desktop 0.2.2-rc.3 的会话格式。接续前用同一个 Python 环境运行 `python -c "import zstandard"`。如缺少模块，可在允许安装依赖时执行 `python -m pip install zstandard`。常规命令行调用无需此模块。

1. 读取错误给出的 `<步骤>.desktop.json`。记录中的 `workspace` 指固定桌面工作区，`request` 指任务运行目录里的 `<步骤>.desktop-request.txt`。原始请求包含共同目标、证据、文件快照、上一轮决定和本轮协作记录编号。桌面工作区本身保持为空，避免混入其他任务的材料。
2. 用环境支持的桌面操作工具打开 DeepSeek Harness。先按路径核对并复用已有的「Codex + DSH 协作」。首次才点侧栏「添加工作区」，在系统选择器输入 `workspace`。Windows 原生选择器如果无法按控件编号点击，用最新截图点「文件夹」输入框，核对路径再确认。若本轮记录编号已经发过，查看原会话。否则从这个工作区打开新会话并核对输入框上方的工作区。
3. 按交接记录的 `provider` 和 `model` 选模型。国内 `workbuddy` 在 **WorkBuddy** 分组，国际 `workbuddy-global` 在 **WorkBuddy Global** 分组。选择对应的 DeepSeek V4.1 Flash 或 Hy4 Preview；DeepSeek 官方分组也可能有同名模型。在本轮会话里只发送一次 `request` 指定的正文。遇到登录或工具阻碍，保存现状并说明原因。
4. 等回复完成后，从会话侧栏「… → 复制会话 ID」获取 ID。用原参数（含本轮 `--route`）重跑脚本，在 `--check` 之前加入 `--desktop-session-id <会话ID>`。脚本核对完整请求、工作区、模型来源和完成状态，再导回回复并执行原有验收。可附加 `--desktop-answer <回复文件>` 比对手工保存的文本。
5. 若本地记录还在写入，等当前会话保存后用同一 ID 再试。同一轮导回会绑定首次核对通过的会话和答复。若目标、材料或 Skill 升级后的提示词已变更，用新记录审查当前版本。

桌面接续会在「Codex + DSH 协作」下新建一条可见会话。命令行会话保存在 DSH 本机的会话存储里，可能出现在「未分组」，也可尝试用会话首句或标题搜索。已有桌面窗口不保证立即列出另一个进程刚写入的会话。找不到时先用运行报告的 `session_id` 和日志确认保存情况。
