# 项目对标

影响新项目、架构、主要功能或重要用户流程时用。已知原因的小修复按需查证。若本机装有 `benchmark-product-workflows`，读取其 `SKILL.md` 做现状基线、产品对标和改后验收。以下流程也能独立使用。

1. 用当前用户任务和硬约束界定要比较的问题，保留现状或最简单可行方案作为对照。广搜同类产品、同功能的不同做法和跨领域机制，去重后深查可能改变决定的候选。样本少时说明覆盖范围，用本地基线或小实验补查，数量按任务大小调整。
2. 每个有用做法用稳定短标题记录，附一手链接、版本或查证日期、观察范围、迁移前提和一个本地验证。外部能做到和本项目适合做分别核实。
3. 把相关条目放进 `benchmark.md`，用 `--benchmark` 交给 DSH。现状与假设走 `--context`，本机实测走 `--evidence`。用户原始目标和验收标准保留在 `goal.txt`。DSH 先独立提出选法或反例，Codex 核实后决定。摘录默认沿用，后续新步骤可以传新版或用 `--clear-benchmark` 撤回。正在等待桌面接续的请求已固定，材料变化时用新记录发起审查。
4. 用同一用户任务比较改前改后，核实会改变决定的分歧。在协作小结链接外部来源和本机验证，说明什么条件下要重看决定。完整候选池留在本地。只做调研时交付证据和建议。
