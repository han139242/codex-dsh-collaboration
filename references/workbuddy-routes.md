# WorkBuddy 模型回退

1. 默认 `--route auto`。首次按国内 DeepSeek V4.1 Flash（`cn-flash`）、国际版同款（`global-flash`）、国内 Hy4 Preview（`cn-hy4`）、国际版 Hy4 Preview（`global-hy4`）依次尝试。后续先用同任务最近返回可用回复的路线，自动模式跳过已明确报告 `UNKNOWN_MODEL` 的路线。四条路线均走 WorkBuddy 插件和现有账号。
2. 命令行写出完整回复但进程仍未退出时，读取结果并收尾。每条路线达到 `--timeout` 后还会查已保存的本地会话。找不到完整回复或审查报告无法解析时才试下一条。各路线独立留日志，超时交接文件标记本轮等待上限和最后的命令行状态。收到完整审查意见即继续核实和验收，意见有问题、待确认或本机验收失败时依实际证据处理。
3. 自动模式在所有命令行路线尝试完后才给出桌面接续提示（有可接续的超时记录时），优先选回退顺序里最早超时的路线。没有可用回复或桌面无法接续时，由 Codex 继续核查并说明缺口。用户可用任一具体的 `--route` 只尝试指定线路。

讨论、审查、复查和切换路线沿用同一个 `--run-dir`。脚本记录唯一会话 ID，后续用 `--session-id` 续聊。不确定原会话 ID 时停止重试，防止产生重复会话。各路线仍有独立的本地日志，正式报告注明实际供应商、模型和路线。同一轮已有交接记录时，自动模式只查原会话的完整回复。需要显式尝试另一条路线时指定 `--route`。
