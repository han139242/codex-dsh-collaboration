# ISO/IEC 25010:2023 产品质量检查

这份检查表把标准的九项产品质量特性转成开发和验收问题。需要系统查漏或用户指定标准时选用。用它做整体审查时，先扫九项，再按风险选验证深度。标准版本与范围见 [ISO 官方页面](https://www.iso.org/standard/78176.html)，特性与子特性见 [GSO 采纳版预览](https://gso-sims-preview-doc-aws.s3-eu-west-1.amazonaws.com/gso-iso-iec-25010-2025-en.html)第 3、4 节。

| 质量特性 | 优先核对的问题 | 可保存的证据 |
| --- | --- | --- |
| 功能适合性（Functional suitability） | 指定的角色和任务是否都能从入口做到预期结果？结果是否准确？步骤是否有助于完成任务？ | 需求—角色—任务—验收映射，正例、边界和失败回退 |
| 性能效率（Performance efficiency） | 常用负载下响应、资源占用和容量能否满足目标？ | 固定数据量和并发下的耗时、资源占用及测量条件 |
| 兼容性（Compatibility） | 能否和预期系统共存、按约定交换数据？ | 真实版本、平台与接口的互操作检查 |
| 交互能力（Interaction capability） | 用户能否知道从哪开始、当前在做什么、下一步怎么走？误操作或失败后能否恢复？ | 从真实入口完成任务，记录步骤、状态、错误提示和恢复操作；按用户场景检查键盘、焦点和可读性 |
| 可靠性（Reliability） | 调用失败或中断后如何恢复？会不会重复执行或丢失进度？ | 超时、崩溃、重试和恢复前后的结果对照 |
| 信息安全性（Security） | 数据、密钥和操作权限是否符合边界？能否追踪关键操作？ | 权限验证、凭据与记录脱敏检查、可审计的操作记录 |
| 可维护性（Maintainability） | 能否定位问题、修改局部并验证影响？ | 诊断步骤、变动范围、自动化回归或最小复现 |
| 灵活性（Flexibility） | 环境、配置、数据量或模型变动时是否仍能完成同一任务？ | 安装、切换、扩容或替换前后的同口径验证 |
| 安全性（Safety） | 误动作或故障会不会造成人身、财产或环境伤害？若有风险，能否限制操作、告警并进入安全状态？ | 危险场景、限制条件、告警和安全降级验证 |

## 优先验收功能完备性和交互能力

- **功能完备性是功能适合性的子特性。** 先列用户指定的角色、任务和目标，再把每个任务映射到入口、关键分支、完成结果和待验证证据。入口存在或页面能打开只能证明可达；成功、失败、恢复和权限等分支按业务需要验证。未覆盖的任务标明影响。
- **交互能力从用户走完任务来核查。** 看入口能否被发现、当前状态和下一步是否说清、错误能否恢复、重复操作是否安全。任务耗时较长时检查等待提示和退出恢复；涉及多模型时检查当前由谁处理、用了什么材料，以及用户如何看到结论和依据。

## 写成能复查的结果

按「特性 / 用户任务与场景 / 验收或阈值 / 验证方式与环境 / 结果与证据」填写。结论使用「通过」「有缺口」「待验证」或「不适用（写明原因）」。只做方案调研时，外部产品证据和自身实测分别记录。审查时，模型意见、Codex 的核实和实际验收结果分别保留。重大缺口优先修订再复测。覆盖结果用于本任务验收，不作为标准认证结论。
